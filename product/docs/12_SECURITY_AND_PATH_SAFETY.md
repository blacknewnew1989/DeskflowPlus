# 12 内部使用最低安全与文件路径保护

## 1. 原则

RelayDesk 仅在内部局域网使用，不做过度安全防御。安全实现只服务于两件事：

1. 避免把文件写到用户选择目录之外；
2. 避免传输中断或损坏后把半成品当成完成文件。

不建设：

- 账号、RBAC、组织、租户；
- 零信任、WAF、DLP、SIEM；
- 病毒扫描、内容审查、文件类型白名单；
- 复杂限速/配额/风险评分；
- 自研密码学协议；
- 阻断开发的安全审批和扫描门禁。

## 2. 设备连接

- 复用 Deskflow/Qt/OpenSSL 现有 TLS 能力；
- 保存已配对设备的 deviceId 和证书指纹；
- 指纹变化时提示重新配对；
- 私钥和真实凭据不提交 Git；
- 不自动执行收到的文件。

## 3. PathPolicy

协议中的文件路径必须：

- UTF-8；
- 相对路径；
- 使用 `/` 分隔；
- 不含 NUL；
- 不含 `.`、`..`；
- 不接受盘符、UNC 和绝对路径；
- Windows 端处理保留名、结尾点/空格和 ADS；
- 最终路径必须位于用户选择的接收根目录内。

P0 默认跳过发送端符号链接和特殊文件，并使用应用自建接收目录；不实现逐级句柄遍历、竞态加固或企业安全框架。

## 4. 临时文件和完成

```text
目标文件.part
→ 流式写入
→ 完成后检查大小/SHA-256
→ 原子改名
```

- 失败时保留或清理 `.part`，由任务策略决定；
- 正式文件只在完整性检查通过后出现；
- 同名默认自动重命名；
- 覆盖时先保护原文件，失败不得损坏原文件。

## 5. 资源边界

只设置防止明显内存失控的实现边界：

- 文件流式读写；
- 有界 socket 队列；
- manifest 分页/分批；
- 不按远端长度一次性分配巨大内存；
- 目录扫描和哈希不阻塞 GUI。

具体上限由实际测试调优，不建立复杂配额管理。

## 6. 日志

可记录任务 ID、设备 ID、状态、字节数和错误码。默认不记录私钥、配对码、文件内容和剪贴板内容。

## 7. 最低测试

- `../` 和绝对路径；
- Windows 保留名/ADS；
- 发送端链接条目跳过；
- 0B/大文件；
- 网络中断；
- hash mismatch；
- 磁盘满；
- 同名冲突；
- `.part` 完成与清理。

测试失败由 Codex 修复，不新增人工审批门禁。
