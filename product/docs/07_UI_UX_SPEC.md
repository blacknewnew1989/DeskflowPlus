# 07 UI/UX 规格

## 1. 原则

- 小巧、现代、清晰，不做传统“服务器配置表单堆砌”。
- 首页先显示设备和状态，技术端口放高级设置。
- 日常操作不要求理解 Server/Client，但高级页面保留与 Deskflow 兼容的角色配置。
- 传输失败必须告诉用户下一步，而不是只显示错误码。
- 中文为首要体验，同时保留英文 i18n。
- 动效短、可关闭，不影响键鼠响应。
- Windows 与 macOS 使用共享 Qt 信息架构、组件语义和状态模型；平台层只提供权限、
  tray/menu bar、系统设置和原生窗口行为适配。

### 1.1 已确认设计基线

实现基线：[`product/assets/design/relaydesk-compact-ui-approved-20260814.png`](../assets/design/relaydesk-compact-ui-approved-20260814.png)。
设计稿于 2026-08-14 经用户确认。本规范负责把设计稿转换为可测试的布局与行为约束；
图片本身不是实现完成证据。

| 项目 | 规格 |
|---|---|
| 默认窗口 | `560 × 420 logical px` |
| 最小建议窗口 | `520 × 380 logical px` |
| 布局 | 单栏；不使用常驻侧栏或仪表盘网格 |
| 顶栏 | `52 px`，包含 Logo/产品名、全局状态、历史、设置 |
| 权限摘要 | 单行；显示最高优先级待处理项和直接动作 |
| 设备条目 | 两行语义；首行设备名/主操作，次行连接、信任和能力 |
| 迷你传输条 | `52 px`；文件、进度/速度、主控制动作 |

尺寸均为 logical px。系统缩放、较长翻译或辅助字号导致内容无法容纳时，应让内容滚动、
压缩非关键留白或扩大窗口，不得裁切权限动作、设备主操作和传输控制。520×380 是建议的
紧凑下限，不是绕过可访问性的硬裁切尺寸。

### 1.2 临时 Logo 与图标语义

- 临时 Logo 为原创“双设备 + 中继点”：两个相对设备轮廓由中心中继点建立协作关系；
- `product/assets/branding/relaydesk-mark.svg` 是几何单源，不分别手绘尺寸变体；
- App、安装包和关于页使用彩色版本；Windows tray 与 macOS menu bar 使用同一几何派生的
  单色版本；
- 标记在 `16 px` 必须仍能分辨两个设备和中继点，不能依赖细线、小字或渐变才能识别；
- macOS menu bar 资源使用 template 渲染，由系统适配浅色/深色；不得直接缩小彩色 App 图标；
- RelayDesk 仍是临时代号，品牌资产不得复用 Deskflow 标志，也不得暗示官方关联。

## 2. 信息架构

```text
首页 / Devices
├── 52 px 顶栏：品牌 / 全局状态 / 历史 / 设置
├── 单行权限摘要
├── 我的设备：已配对 / 已发现设备
├── 52 px 当前传输摘要（存在活动任务时）
└── 本机摘要

传输 / Transfers
├── 进行中
├── 等待接收
├── 已完成
└── 失败/可重试

设置 / Settings
├── 常规
├── 键鼠
├── 剪贴板
├── 文件传输
├── 发现与网络
├── 信任设备
├── 开机启动
└── 高级/日志

关于 / About
├── 版本
├── 上游与许可证
└── 诊断
```

首页保持单栏，不设置常驻导航侧栏。历史和设置从顶栏进入，传输条进入传输详情；配对、
设备详情和屏幕布局从“添加”或设备“更多”进入。两平台必须复用以上层级和同一套语义 key，
不得因为 macOS 使用 menu bar 就另建平台私有首页。

## 3. 首页

### 顶部状态

```text
[Logo] RelayDesk        ● 在线        [历史] [设置]
```

顶栏固定 `52 px`。全局状态使用短标签，不在首页重复展开“键鼠服务/文件服务/监听端口”；
用户点击状态或进入设置后查看分能力详情。历史和设置按钮只使用图标时必须提供 tooltip、
accessible name 和清晰焦点态。

状态只使用：

- 正常；
- 正在连接；
- 需要授权；
- 已暂停；
- 错误。

### 单行权限条

权限条位于顶栏下方，只显示一个摘要和一个主动作：

```text
[状态图标] 输入监控未开启                         [去开启]
```

- 多项未就绪时显示当前最高优先级且最可操作的一项，点击整条进入权限详情；
- 全部就绪时显示低强调度“权限就绪”，保持布局稳定；
- 摘要不得写成“应用不可用”；应精确说明受影响能力；
- 条内文案保持单行并省略非关键信息，不能把三项 macOS 权限堆叠进首页；
- 权限变化通过共享 `PermissionSnapshot` 更新，不以字符串解析驱动业务。

### 设备卡片

```text
┌─────────────────────────────────────────────────┐
│ [设备] ● MacBook Air             [发送] [更多] │
│          已连接 · 键鼠 / 剪贴板                │
├─────────────────────────────────────────────────┤
│ [设备] ○ 书房 Mac mini           [连接] [更多] │
│          可信 · 点击连接                        │
└─────────────────────────────────────────────────┘
```

每个条目固定为两行信息语义：首行承载设备识别和一个主操作，次行承载连接/信任状态与
可用能力。设计稿中的两台设备分别示例“在线已连接”和“可信待连接”，不表示首页固定只显示
两台；更多设备继续在同一单列中滚动。主操作随状态变为“配对”“连接”“发送”或不可用原因，
“更多”承载设备详情、屏幕位置、重命名和撤销信任。

卡片状态：

- discovered/unpaired；
- pairing；
- trusted/offline；
- trusted/online；
- trust violation；
- permission required；
- file transfer busy。

Drop feedback：

- hover 高亮；
- 显示文件数和总大小；
- 非本地文件/不可读项立即提示；
- 松开后进入准备清单，不直接无提示发送到陌生设备。

### 迷你传输条

存在活动、暂停或失败待处理任务时，在设备列表下显示一个 `52 px` 传输条：

```text
[文件] 设计稿.zip              68% · 12.4 MB/s  [暂停]
                                      ━━━━━━━━
```

- 单任务显示文件/任务名、百分比、速度、进度和一个当前主动作；
- 多任务显示当前最活跃任务，并附“另有 N 项”；
- 点击非按钮区域打开传输中心；
- 主动作按状态切换为暂停、继续或重试，取消放在详情页以减少误触；
- 无相关任务时移除该条，由设备列表使用空间，不保留空卡片。

### 本机摘要

窗口底部单行显示本机名称，例如“本机 · 工作室 PC”。详细地址、端口和诊断只在设置中显示。

### 屏幕布局

屏幕布局从设备“更多”进入独立紧凑页面，不占用首页常驻空间。复用/改进上游布局：

- 卡片可拖动相对位置；
- 显示当前主控；
- 显示跨屏边界；
- 支持上下左右；
- 防止完全重叠；
- 提供“自动排列”和“恢复默认”。

## 4. 配对向导

步骤：

1. 选择发现设备；
2. 双方确认设备名；
3. 显示/输入六位码；
4. 显示简短指纹；
5. 成功；
6. 可选设置自动接收和屏幕位置。

错误文案：

- “配对码已过期，请重新生成。”
- “对方证书已变化，为保护设备，已停止自动连接。”
- “多次输入错误，请稍后再试。”
- “两台设备不在可直连网络中，可使用手动地址。”

## 5. 发送流程

### 应用内拖放

1. 用户拖到设备卡片；
2. 本地异步扫描；
3. 弹出轻量确认：
   - 目标；
   - 文件/文件夹数；
   - 总大小；
   - 发现的不可读/不支持项；
4. 发送；
5. 首页卡片显示微型进度；
6. 传输中心显示详情。

已开启“对该信任设备自动接收”时，发送方仍显示已发送；接收方无需确认，但有系统通知。

### 快速发送

- 卡片按钮；
- 托盘菜单；
- 快捷键；
- 文件/文件夹选择器；
- 最近设备排序。

## 6. 接收流程

Incoming Offer：

```text
MacBook Pro 想发送
“Project”
42 个文件 · 1.2 GB

保存到：Downloads/RelayDesk
冲突：自动重命名

[拒绝] [更改设置] [接收]
[ ] 始终自动接收此设备的文件
```

安全：

- 不显示远端提供的富文本；
- 名称转义；
- 不自动打开；
- 未信任设备不会出现普通接收按钮，而是先配对。

## 7. 传输中心

每个任务：

- 方向图标；
- peer；
- 标题；
- 总进度；
- 当前文件；
- 已传/总字节；
- 速度；
- ETA；
- 状态；
- pause/resume/cancel/retry；
- 完成后“打开目录”。

状态文案：

```text
正在准备
等待对方确认
排队中
正在传输
已暂停
连接中断，等待恢复
正在校验
正在保存
已完成
已拒绝
已取消
失败
```

不要把 `RESUME_QUERY` 等协议名暴露给普通用户。

## 8. 设置

### 常规与后台运行

- “最小化后隐藏到托盘”：默认开启，可关闭；
- “关闭窗口后继续在托盘运行”：默认开启，可关闭；
- 两项设置分别保存。关闭第一项后，最小化遵循系统普通窗口行为；关闭第二项后，关闭主窗口
  执行真正退出；
- 第一次关闭到托盘时显示一次“RelayDesk 仍在后台运行”的非阻塞提示，提供“知道了”和
  “打开设置”；确认记录持久化，升级或重启后不重复提示；
- 操作系统退出、注销或应用更新触发的退出不显示该提示，也不得被“关闭到托盘”拦截。

### 文件传输

- 默认接收目录；
- 接收策略：每次询问 / 信任设备自动接收；
- 冲突策略；
- 完成通知；
- partial 保留天数；
- 历史保留；
- 最大并发（高级）；
- 带宽限制（P1）。

### 信任设备

每台：

- 别名；
- 指纹；
- 自动接收；
- 最后在线；
- 撤销；
- 重新配对。

### 高级网络

- 发现开关；
- 手动地址；
- file port；
- 绑定接口；
- 代理：P0 不支持文件通道代理；
- 诊断连接。

## 9. 平台权限引导

权限详情使用共享行结构：权限名称、用途、状态、受影响能力和主动作。公共状态限定为：

```text
Unknown / NotRequired / Granted / Denied / NeedsAction
```

以上名称与冻结的 `PermissionState` 一致。平台 adapter 将系统真实结果保守映射到这些状态；
探测不到时保持 `Unknown` 并显示“无法检测”，不得伪装成 `Granted`。探测、打开系统设置和
回前台刷新不得阻塞 GUI 线程。

### macOS

三项权限必须独立呈现，不能合并为一个“系统权限”总开关：

| 权限 | 面向用户的用途 | 缺失时门控 | 主动作 |
|---|---|---|---|
| Accessibility | 允许依赖辅助功能的跨设备键鼠控制 | 只禁用依赖它的输入方向 | 打开“辅助功能”设置 |
| Input Monitoring | 允许读取用于共享的全局键盘/鼠标输入 | 只禁用依赖它的输入方向 | 打开“输入监控”设置 |
| Local Network | 发现并连接局域网内设备 | 降级发现与直连；说明文件连接受影响 | 打开“本地网络”设置 |

- 每行显示自身状态与用途；授权一项不得把另外两项标为已授权；
- 点击主动作只能打开相应系统设置或最接近的隐私设置页，不能声称自动授予；
- 应用从后台回到前台时，对三项执行防抖、异步复检并刷新首页单行摘要；无需用户重启；
- 缺少 Accessibility 或 Input Monitoring 时，只门控受影响的键鼠能力；只要网络路径可用，
  文件发送、接收、历史和设置必须继续可用；
- 缺少 Local Network 时不能笼统显示“输入权限问题”，应给出发现/连接降级原因；
- 系统拒绝后不循环触发权限请求，用户仍可稍后从权限详情重试。

### Windows

- 防火墙允许；
- 管理员/UAC 能力限制说明；
- 自启动开关；
- 服务状态（仅上游实际存在时）。

Windows 同样按能力门控：防火墙不可用只影响相应发现/入站连接提示，不得把本地历史、
设置或无关能力整体锁死。

## 10. 托盘、菜单栏与应用生命周期

共享行为：

- 最小化到 tray/menu bar；
- 按“关闭窗口后继续运行”设置决定关闭主窗口是隐藏还是退出；
- 单击平台惯例动作或菜单“显示 RelayDesk”恢复并激活主窗口；
- 菜单提供“显示 RelayDesk”“暂停共享/继续共享”“退出”；
- “暂停共享”暂停键鼠/剪贴板共享入口，但不取消正在进行的文件传输；界面必须明确显示
  文件传输仍在运行；
- 菜单“退出”永远是真正退出，不受关闭窗口设置影响。

真正退出必须先停止接收新操作，再释放可能残留的按键/修饰键状态，保存可恢复传输检查点，
关闭监听器和服务，移除 tray/menu bar 图标，最后结束应用事件循环。退出失败不得悄悄隐藏
进程；可恢复错误写日志，存在数据损坏风险时显示简短可操作提示。

Windows 使用单色 tray 资源。macOS 使用菜单栏单色 template 图标，并遵循系统菜单命名与
键盘习惯；彩色 App 图标只用于 Dock/Finder/关于页。共享 Qt 层拥有菜单意图和生命周期
状态，平台 adapter 只负责系统图标、激活和设置入口。

## 11. i18n

使用语义 key：

```text
devices.status.online
pairing.code.expired
transfer.state.verifying
transfer.error.disk_full
transfer.action.open_folder
permission.macos.input_monitoring.purpose
permission.action.open_system_settings
tray.action.pause_sharing
tray.notice.still_running
```

禁止将完整中文句子作为业务判断条件。

格式：

- 数量使用 plural；
- 文件大小本地化；
- ETA 本地化；
- 路径保持平台格式；
- 错误诊断可复制英文技术详情。

## 12. 可访问性

- 所有图标有 accessible name；
- 键盘可完成配对、发送、暂停；
- 焦点顺序合理；
- 不仅靠颜色表达状态；
- 进度条有文本；
- 16 px Logo/tray 图标在浅色、深色和高对比模式下仍可识别；
- 支持系统高对比/减少动效；
- 字号遵循 Qt/system scaling。

## 13. 首版不做的 UI

- 社交账号头像；
- 云端设备列表；
- 团队/组织；
- 复杂统计大屏；
- 皮肤商城；
- 文件浏览器；
- 双栏同步器；
- 原生拖拽幽灵跨系统延续。
