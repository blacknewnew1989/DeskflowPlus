## PROTO-FREEZE-001 只读审计

以下项目由 A0/A2/A3/A6/A7 统一冻结，A5 不在 macOS 端补出私有协议。

### 已在产品基线关闭

- `ProtocolMessageRegistry.def` 已作为 24/24 MessageType 单一机器注册表，
  registry 测试检查唯一性、codec/schema target 和每种消息的正负向量覆盖。
- `test-vectors.json` 现有 60 个向量：24 个 frame 正例、25 个 metadata 负例、
  11 个 frame 负例；真实 codec 往返校验冻结字节。
- `ProtocolMessageRegistry.cpp` 与 `FrameCodec.cpp` 统一执行 flags、stream、
  metadata 与 payload envelope 校验。
- `IFileTransferService` 的方法与信号签名已有编译期和 Qt 元类型冻结测试；
  `TransferStartResult` 返回 typed 启动失败，cancel 使用 typed
  `TransferCancelOptions`，acceptance origin 也已具名化。
- `TransferId` 与 `FileId` 已从 QUuid alias 收敛为强类型 wrapper；转换、比较、
  hash、Qt metatype 和空值语义由 `RelayDeskStrongIdTests` 固定，现有 wire
  编码仍使用相同 16-byte UUID 表示，60 个冻结向量保持通过。
- `AutoReconnectCoordinator` 只消费 connector 已认证的 identity/fingerprint。
- `IPairingService` 是 GUI/组合层唯一 pairing 边界，只接收 DeviceId；runtime
  内部解析实时 snapshot、fingerprint 与 endpoint。
- `FileEndpointAnnouncement` 将文件端点公告收敛为强类型原子值。
- `IPlatformPermissions` 已定义 typed `PermissionOpenResult`；macOS 与 Windows
  probe 均实现该接口，并有派生关系及 enum 值测试。
- `IPlatformFileSafety` 已定义 typed request/result/error/disposition，并由
  `RelayDeskPlatformFileSafetyContractTests` 固定代码接口；receiver wiring 与
  平台 adapter 明确尚未完成。
- 新版 `05_FILE_TRANSFER_PROTOCOL.md` 已关闭两项旧冲突：TransferResume 仅携带
  transferId；unknown-key 策略按 codec family 区分，并与测试一致。
- `18_SHARED_CONTRACTS.md` 已改为索引真实 header，并对齐 pairing、strong ID、
  transfer service/options、permission、file safety 与各项 `NOT_WIRED` 状态。
- `19_PROTOCOL_V1_FREEZE.md` 已建立 freeze index；`validate-package.py` 现在检查
  该索引、24 个 registry message、60 个向量及 workflow/tag 触发条件。
- shared interface freeze 已增加真实 `Qt::QueuedConnection` 跨 QThread smoke，
  覆盖 ID、snapshot、offer、options/result 和 permission values 的 queued copy。
- sender worker 到 TLS transport 已改为容量 signal 驱动，移除 5 ms 轮询；
  socket-owning thread 经 `FileTlsFrameSink` 提交 immutable frame，worker 在背压
  期间保留原 frame 且不继续读/哈希源，并有 runtime/transport/sender 定向测试。
- discovery 在 incoming receiver 未组合前强制发布 disabled file endpoint，不再
  对局域网声明不可执行的接收能力。
- `TransferUiRuntime` 现在注入唯一 `IFileTransferService`，将 send、accept、reject、
  pause、resume、cancel、retry typed intent 及 service snapshot/offer 信号直接连接
  到 model；旧的第二套 UI business signals 已删除。
- `ReceiveOptions::keepPartialOnFailure` 与 `FileReceiver::cancel(bool)` 已分别改为
  `PartialDisposition`，消除跨 service/receiver 的裸 bool 语义。

### 仍开放，禁止由 A5 私自补齐

1. 冻结发布证据与标签

   - docs05、docs18、docs19 都明确仍是 freeze candidate；docs19 中
     authoritative commit、freeze tag、canonical Actions run、Windows/macOS
     artifact 与 SHA-256 仍是占位值。
   - docs19 当前要求同一 tagged commit 内预先写入只能在 tag/Actions 后获得的
     run 与 artifact digest，存在时序自引用；A0 需把不可变候选 commit 与外部
     evidence 拆开，或调整最终填充语义，避免事后改文档使 tag 不再直指该 commit。
   - docs19 的 file-service 索引尚未点名新 `AcceptanceOrigin`、
     `TransferCancelOptions`、`PartialDisposition`；validator 目前只接受占位符，
     未验证接口签名、docs18 对齐或真实 tag reachability。
   - GitHub 远端无 `relaydesk-protocol-v1-*` 标签，当前最新产品提交尚无对应
     双平台 Actions 和 artifact 证据。因此 A5 仍按 pre-freeze 边界工作。
   - Owner：A0 填充最终证据、创建不可移动标签并监控唯一双平台 Actions。

2. 稳定错误码

   - docs18 已明确 v1 不设全局 `ProductError`，而由各 boundary 的 typed enum
     冻结稳定错误；这关闭了“必须建立单一全局错误对象”的旧歧义。
   - 但 `TransferSnapshot::errorCode` 与 `FileTransferRuntime` 仍使用裸 int；wire
     向量把 `1002` 定义为 `INVALID_FRAME`，runtime 又把 `1002` 用作
     `kOfferFailed`。在最终 freeze 证据中仍需明确这些数字是否属于隔离命名空间，
     或迁移到已登记的 boundary enum，不能由 A5 自行裁定。
   - docs18 还引用不存在的 `FrameError`；真实类型为 `FrameDecodeError` 与
     `ProtocolEnvelopeError`，需由 A6/A0 对齐。
   - Owner：A0/A6 明确 transfer snapshot/runtime 错误边界并补冻结证据。

3. FileTransferRuntime 与生产组合

   - `accept`/`reject` 仍为空；receiver 和 `incomingOffer` 未组成闭环。
   - pause/resume/cancel 虽已有 typed options，但仍只改本地状态；router 仍只处理 Accept、Reject、
     FileResult；发送完成仍只改本地 Completed，未交换完整完成握手。
   - Checkpoint/Resume/Heartbeat/Goodbye/Error 未形成完整 runtime composition；
     `TransferUiRuntime` 的 service adapter 已闭合，但生产 `MainWindow` 仍未创建
     `FileTransferRuntime`/`TransferUiRuntime`，所以用户启动路径仍不可达。
   - outgoing sender/sink/backpressure 边界已实质推进，但不代表 incoming、control、
     completion 或产品组合已完成。该实现仍在 `FileTransferRuntime` 内新增私有
     `SenderFrameBridge` 并计算 high/low/queued bytes，与 docs18“应用 runtime
     不得另建私有 sink、水位算法”的字面规则冲突，需 A6/A0 统一边界。
   - 当前 2 MiB 定向用例低于 16 MiB high-water，尚未覆盖真实背压 E2E、
     capacity signal、多并发 sender、断连及 pause/cancel 时的 pending frame。
   - Owner：A6 完成 runtime，A0 完成生产 composition；A3 只消费冻结 service。

4. 其余平台抽象

   - `IPlatformPermissions` 代码接口与 docs18 已同步。
   - `IPlatformFileSafety` 代码契约已进入产品分支，但其注释和测试明确标记
     FileReceiver `NOT_WIRED`；macOS 真实文件系统 adapter 尚未实现。冻结标签发布前，
     A5 只验证该共享接口，不提前形成平台私有 wiring。
