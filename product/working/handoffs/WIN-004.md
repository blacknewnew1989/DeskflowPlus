## Signing behavior

- No signing identity: the package flow continues without SignTool and emits explicit `unsigned` names plus `artifact-manifest.json` with `signed=false`.
- Signing identity configured: the flow requires SignTool, signs and verifies built EXE/DLL payloads before CPack, produces a `signed` portable archive containing those signed files, then signs and verifies the MSI before artifact collection.
- PFX file and Windows certificate-store thumbprint modes are mutually exclusive.
- PFX passwords are accepted as `SecureString`; `RELAYDESK_WINDOWS_SIGN_PASSWORD` is converted immediately to `SecureString`.
- Optional CLI/environment inputs cover certificate path, thumbprint, timestamp URL, and SignTool path. No workflow secret or credential value was added to the repository.
- SignTool command arguments are not logged. Failure diagnostics mask password, certificate path, and thumbprint before throwing a stable `WIN_SIGNTOOL_FAILED` error.
- A configured signing operation fails closed: a failed signature or verification cannot be labeled `signed`.
- The normal development workflow remains unsigned and has no release approval or required-check gate.
