## Implementation

- `WindowsFirewallProbe` runs Windows Firewall COM rule inspection and IP Helper TCP listener inspection on a worker pool.
- Firewall results distinguish explicit block, matching allow, missing allow, disabled active profiles, and unavailable inspection.
- Listener results require every requested TCP port to be owned by the requested/current process.
- Results publish the shared `PermissionSnapshot` entries for `WindowsFirewall` and `WindowsListeningPort` with stable `4101`, `4102`, or `4000` codes.
- Only the firewall entry can open Windows Firewall settings; listener diagnostics do not claim a settings action.
- Non-Windows builds retain guarded unsupported behavior and never report either check as granted.

## Cross-platform follow-up

- macOS/Linux should only verify guarded compilation; Windows-only checks intentionally return `Unknown` / `ProbeUnavailable` there.
- No platform should map an unavailable probe to `Granted`.
