## Implemented behavior

- Uses only `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`; no administrator rights, service, or scheduled task.
- The stable Run value name is defined by `RELAYDESK_WINDOWS_RUN_VALUE_NAME` in the centralized product brand configuration.
- Query reports `Disabled`, `Enabled`, or `Stale`. A stale entry preserves the user's enabled intent and is rewritten to the current executable path when preferences are saved.
- Enable, disable, read, write, delete, and post-write verification failures have stable `StartAtLoginErrorCode` values plus the native Win32 error and an internal diagnostic.
- Windows command-line quoting follows the backslash/quote rules and always protects an executable path containing spaces.
- Registry access is injected through `IWindowsRunRegistry`; production uses the native adapter and deterministic tests use a fake adapter.
- The GUI registers `"<current application path>" --start-in-tray`. The option is parsed by the existing GUI entry point and hides the main window while retaining its tray/core startup behavior.
- The existing `gui/startCoreWithGui` setting remains separate: it controls whether the Deskflow core starts after the login-launched GUI. The daemon/service architecture is unchanged.
- Non-Windows builds compile the adapter behind `Q_OS_WIN`, report `UnsupportedPlatform`, and hide the Windows-only preference.

## Windows verification

Environment:

- Windows 11 `10.0.26200.0`
- Qt `6.7.3` MinGW 64-bit
- GCC `13.1.0`
- CMake `3.30.5`

Commands executed with local, ignored CMake harnesses:

```text
cmake -S build/win002-harness-src -B build/win002-harness -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=<Qt-6.7.3>
cmake --build build/win002-harness --parallel 4
ctest --test-dir build/win002-harness --output-on-failure

cmake --build build/win002-gui-compile --target win002_settings_compile --parallel 4
cmake --build build/win002-gui-compile --target win002_main_window_compile --parallel 4
cmake --build build/win002-gui-compile --target win002_gui_entry_compile --parallel 4
```

Results:

- `RelayDeskWindowsStartAtLoginTests`: PASS, 8 test cases including a real temporary HKCU Run value enable/query/disable round trip; the temporary value was removed.
- `SettingsDialog.cpp` plus generated UI: PASS object compilation.
- `MainWindow.cpp` plus generated UI: PASS object compilation.
- `deskflow-gui.cpp`: PASS object compilation with a harness-only compatibility declaration for `SetCurrentProcessExplicitAppUserModelID` because this MinGW SDK lacks upstream's `shobjidl_core.h` header name.
- `git diff --check`: PASS.

Full upstream application configure/link is `NOT_RUN`: the installed Qt SDK lacks `Qt6LinguistTools`, and automated `aqt` attempts to fetch the `qttools` archive timed out. This did not affect the real WIN-002 static library link, Qt Test executable, native registry round trip, or compilation of every changed GUI translation unit.
