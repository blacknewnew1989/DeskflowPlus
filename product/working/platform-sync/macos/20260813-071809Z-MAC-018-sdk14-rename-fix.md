## Summary

Run `31676551335` exposed that `RENAME_RESOLVE_BENEATH` is absent from the supported Xcode 16.4 /
macOS 15.5 SDK and belongs to a newer SDK generation. The adapter already opens every parent directory
beneath the verified receive root with `O_NOFOLLOW` and passes only one-component leaf names to
`renameatx_np`, so the unavailable flag was redundant. Commit `9b22fc857` retains the macOS 14-supported
`RENAME_NOFOLLOW_ANY` leaf race guard and `RENAME_EXCL` no-overwrite atomicity while restoring the P0
toolchain baseline. No shared type, error enum, protocol message, codec, or vector changed.
